# TypeScript 代码规范

## 代码风格

- 若项目已配置 Prettier，**以项目根目录的 `.prettierrc` / `.prettierrc.json` 配置为准**，无需重复定义
- 若项目未使用 Prettier，使用以下默认风格：
  - 2 空格缩进
  - 行末不保留多余空格
  - 使用单引号包裹字符串
  - 非空行务必以分号结尾
  - 大括号始终使用 K&R 风格（同一行放置）
  - 每个语句后必须换行
  - 导入块之间以空行分隔

## 命名规范

### 文件命名

- 文件名使用 kebab-case：`user-service.ts`
- 测试文件：`*.test.ts` 或 `*.spec.ts`
- 类型/接口文件：`*.types.ts`、`*.interface.ts`

### 变量命名

- 普通变量使用 camelCase 风格
- 常量使用 UPPER_SNAKE_CASE 风格
- 布尔值以 `is`、`has`、`can`、`should` 前缀开头
- 数组使用复数形式或添加 `List` 后缀

### 类型命名

- 接口名不加 `I` 前缀，直接使用 PascalCase
- 类型名不加 `T` 前缀，直接使用 PascalCase
- 枚举成员使用 PascalCase
- 泛型参数使用有意义的名称（如 `TElement`、`TKey`），避免使用单个大写字母（`T`、`K`、`V` 除外）
- 类型定义应体现业务语义，避免使用 `Result`、`Data`、`Info` 等宽泛命名

### 函数命名

- 事件处理函数使用 `handle` 前缀：`handleClick`
- 回调函数使用 `on` 前缀：`onSubmit`
- 数据获取函数使用 `fetch`、`get`、`load` 前缀
- 异步函数使用 `Async` 后缀：`fetchUserAsync`

## 注释规范

- 所有**导出（公共）API**必须有完整的 JS-Doc 注释（中文），包含：
  - **业务背景**：为什么存在此函数/类型，解决什么问题
  - **参数**（@param）：每个参数的作用
  - **异常**（@throws）：可能抛出的异常及条件
  - **返回值**（@returns）：返回值含义
- **内部（私有）函数**至少需要 @param 和 @returns（如适用），业务背景可省略
- 注释说明"为什么"，而非"是什么"
- 复杂核心逻辑（如算法、数据结构、高并发场景）必须有注释说明其核心思路或关键决策
- 包含数学公式或逻辑推导的代码应添加图示或步骤说明
- 单行注释使用 `//`，多行注释使用 `/* */`

## 变量规范

- 优先使用 `const`，避免使用 `let`，禁止使用 `var`
- 禁止在业务逻辑中使用无含义的单字母变量（如 `n`、`m`），优先使用描述性命名体现语义和单位
- 允许在简单循环中使用惯用变量名（如 `i`、`j` 用于索引），但超出嵌套循环时应使用更明确的命名
- 变量命名应使用名词或形容词，避免使用动词；函数命名应使用动词或动词短语
- 避免过度缩写，应使用完整单词（公认的简写除外，如 `config`、`utils`、`req`、`res`）
- 优先使用浅层解构（不超过 2 层）
- 优先使用不可变数据，使用 `readonly` 修饰只读数据
- 使用 `??` 而非 `||` 处理 null/undefined

## 函数规范

- 单一职责，每个函数只做一件事
- 使用卫语句（Early Exit）减少嵌套
- 函数参数不得超过 **4 个**（超出必须用配置对象）
- 单个函数不得超过 **200 行**
- 禁止使用布尔参数控制行为
- `async` 函数内禁止使用 `.then().catch()` 链式调用（必须用 `try/catch`）
- 禁止直接修改入参，使用扩展运算符
- 使用 `for...of` 遍历数组，使用 `Object.keys` / `Object.entries` 遍历对象
- 避免使用 `for...in` 遍历数组

## TypeScript 模式

- 优先使用 `interface` 定义对象类型，`type` 用于联合类型、交叉类型等组合类型
- 使用可空类型（`T | null`/`T | undefined`）而非隐式可空
- 枚举使用 `enum`，或使用 `as const` 对象字面量替代枚举
- 泛型约束优先使用 `extends` 而非类型断言
- 使用可辨识联合类型（Discriminated Union）处理多状态
- 优先使用类型守卫处理类型收窄，必要时使用 `as` 类型断言
- 使用 `unknown` 而非 `any` 处理未知类型数据
- 禁止使用 `any`，使用显式类型标注
- 禁止使用 `Function`，使用明确类型的函数类型
- 非空断言 `!` 仅在类型守卫明确保障后可使用
- 集合类型使用 `Set<T>` 和 `Map<K, V>` 而非普通对象
- 优先使用 `readonly` 修饰只读数据，使用 `Readonly<T>` / `ReadonlyArray<T>` 转换不可变类型
