## Context

参见 `proposal.md` 的 Why。当前 `captureLogPosition()` 已经负责跳过 Node 与 logger 内部帧、选择首个有效调用方帧并丢弃列号，但返回前没有对栈中的文件标识做展示规范化。路径处理需要同时覆盖 Windows、POSIX、`file://`、普通 `node_modules`、pnpm 物理路径和工作目录变化，同时保持采集失败不影响日志写入。

## Goals / Non-Goals

**Goals:**

- 让相同调用点在不同机器上产生稳定、紧凑的路径表示。
- 把路径变换保持为确定性的纯函数，便于直接覆盖边界组合。
- 在不扩大公共 API 的前提下固定 Logger 初始化目录并复用。

**Non-Goals:**

- 不改变首个有效调用帧的选择或新增对其他依赖包帧的过滤。
- 不通过 Source Map 主动把 `dist/*.js` 映射为 `src/*.ts`。
- 不添加路径模式、长度阈值或消歧策略配置项。
- 不为压缩结果添加哈希，也不保证被折叠路径之间唯一。

## Decisions

### 1. 在 LogPosition 内拆分路径解析与路径展示

保留现有栈帧遍历，把文件标识交给一个纯路径格式化函数，再与行号拼成 `path:line`。该函数依次执行：

1. 将 `\` 转为 `/`，规范化受支持的 `file://` 文件 URL。
2. 按完整目录段查找最后一个 `node_modules`；找到时优先截取其后的依赖路径。
3. 否则在目录边界上与初始化目录比较，命中时输出项目相对路径。
4. 未命中时保留统一分隔符后的原始文件路径。
5. 对所得路径执行长度与目录段压缩判断，最后由捕获函数追加行号。

依赖识别优先于项目相对化，避免得到 `node_modules/.pnpm/...` 等仍包含包管理器物理布局的结果。目录边界比较避免把 `D:/app-other` 误判为 `D:/app` 子路径；Windows 驱动器与 UNC 路径比较忽略大小写，POSIX 路径保持大小写敏感。

备选方案是直接保留绝对路径或只取最后固定数量目录。前者不能解决噪声与跨环境稳定性问题，后者会丢失 scoped 包名或业务模块身份，因此不采用。

### 2. 初始化成功时固定项目目录

`LoggerFactoryRuntime` 在首次成功初始化时记录 `process.cwd()`，后续每次采集都把该值传给路径格式化逻辑。初始化失败不得锁定目录；延迟初始化与显式初始化使用同一条成功路径。这样 `process.chdir()` 不会使同一运行时的日志路径前后变化。

该状态属于内部运行时，不新增包根导出、公共类型或 YAML 字段。`captureLogPosition` 和路径格式化辅助函数仍是包内实现细节。

备选方案是在每条日志写入时读取 `process.cwd()`，实现更少但会引入隐藏的运行期变化，因此不采用。

### 3. 120 字符是路径部分的软阈值

长度判断不包含 `:line`。当路径长度超过 120 且至少有六段时，保留前三段与最后两段，并用单个 `...` 替换中间段。五段以内没有可在保持既定身份信息的同时安全省略的目录，因此即使超过阈值也保留完整名称。

已确认接受压缩碰撞，故不计算哈希，也不扫描仓库来判断唯一性。备选的逐段缩写会破坏复制检索能力，哈希方案超出当前简化目标，均不采用。

### 4. 异常路径继续安全降级

路径格式化不得让日志写入抛错。无法识别归属不是错误，直接回退规范化原路径；无法解析栈帧仍由现有事件管线映射为 `-`。文件 URL 解码失败时保留去除协议后的未解码文本，不输出诊断或原始栈。

## Risks / Trade-offs

- [压缩后的路径可能碰撞] → 已由用户接受；保留前三段、最后一级目录、文件名和行号以降低概率，不添加复杂消歧机制。
- [相对路径或 `...` 不一定可被终端直接点击] → 保持 `file:line` 可读格式，并仅对超过阈值的路径插入 `...`。
- [下游按绝对目录前缀检索会失配] → 作为 patch 版本发布并在 README/CHANGELOG 说明，新旧日志无需迁移且可并存查询。
- [平台路径语义不同] → 使用纯函数测试覆盖 Windows 驱动器、UNC、POSIX、文件 URL 与完整目录段匹配。

## Migration Plan

1. 以 `@jintianxiayu/logger` patch changeset 发布，不要求其他 workspace 包同步发版。
2. 部署期间允许旧版本绝对路径与新版本规范化路径同时进入日志平台，不改写存量日志。
3. 如发现下游查询依赖绝对前缀，可暂时锁定上一 patch 版本并回滚；代码回滚不需要配置或数据迁移。
