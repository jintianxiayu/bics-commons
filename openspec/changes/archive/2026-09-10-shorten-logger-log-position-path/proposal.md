## Why

`captureLogPosition` 当前直接输出运行时栈中的完整绝对路径，导致日志冗长、暴露部署目录，并使同一调用点在不同机器上的值不稳定。调用位置只需保留足以定位源码的稳定路径，因此需要在不改变栈帧选择和 `file:line` 结构的前提下规范化并压缩路径。

## What Changes

- 将 Windows 路径分隔符统一为 `/`，并规范化 `file://` 文件 URL。
- 项目内路径去除初始化时确定的工作目录前缀；依赖路径从最后一个完整 `node_modules` 目录段之后开始，保留 scoped 或非 scoped 包名。
- 规范化结果超过 120 个字符时，保留前三个路径段与最后两个路径段，将中间目录折叠为 `...`；压缩碰撞按已确认方案接受，不增加哈希。
- 无法识别项目或依赖归属时保留规范化后的原始路径；始终保留文件名和行号，并继续丢弃列号。
- 保持首个有效调用帧选择、内部帧过滤、配置结构、公共 TypeScript API 和采集失败降级行为不变。

## Capabilities

### New Capabilities

- `logger-log-position`: 定义日志调用位置的跨平台路径规范化、依赖路径识别、超长路径压缩和安全回退行为。

### Modified Capabilities

无。

## Impact

- 受影响包：`@jintianxiayu/logger`，当前版本 `1.0.0`；这是兼容行为修复，changeset 级别为 patch。
- 受影响代码与文档：`packages/logger/src/core/LogPosition.ts`、对应单元测试、`packages/logger/README.md` 和 `packages/logger/DESIGN.md`。
- 公共契约变更：是。`logPosition` / `%{log_position}` 的字段结构仍为 `file:line`，但路径值将从运行环境相关的绝对路径调整为稳定的规范化路径，超长路径可能包含 `...`。
- 兼容性结论：兼容。公共导出、类型、配置、默认开关、错误语义和字段名称均不改变，现行文档也未承诺绝对路径；依赖绝对目录前缀或把字段当作可直接访问文件系统路径的下游可能需要调整查询条件，但这不属于已承诺用法。
- 跨版本日志格式：新旧版本可以同时写入，存量日志无需迁移；检索规则应同时容忍历史绝对路径和新规范化路径，发布不要求消费者与 logger 同步升级。
- 第三方依赖：不新增或修改。
